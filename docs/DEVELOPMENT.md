# Development

## Setup

```sh
npm install          # local devDependencies only
npm run build        # esbuild → dist/extension.js, dist/webview.js
npm run watch        # rebuild on change
```

Press **F5** (launch configuration "Run Extension" in `.vscode/launch.json`) to start an Extension Development Host. After a rebuild, run **Developer: Reload Window** in that window.

## Checks

| Command                   | What it runs                                                                |
| ------------------------- | --------------------------------------------------------------------------- |
| `npm run typecheck`       | `tsc` for the host (Node) and webview (DOM) projects                        |
| `npm run lint`            | ESLint (typescript-eslint)                                                  |
| `npm run format:check`    | Prettier                                                                    |
| `npm test`                | Unit tests (`node:test`), compiled to `out-test/`                           |
| `npm run test:webview`    | The webview in headless Chrome (set `CHROME_PATH` when Chrome is not found) |
| `npm run test:live`       | The HTTP client against the local OpenCode service (skips without one)      |
| `npm run test:acceptance` | End-to-end scenarios in a real VS Code against the local OpenCode service   |
| `npm run package`         | `dist-vsix/opencode-sidecar-<version>.vsix` (never publishes)               |

CI (`.github/workflows/ci.yml`) runs all of these except the live tests and the acceptance harness, on Linux, and uploads the VSIX as an artifact. Pushing a `v<version>` tag runs `.github/workflows/release.yml`, which repeats the checks, creates the GitHub release and publishes to the Visual Studio Marketplace and Open VSX (see `docs/marketplace/MARKETPLACE.md`).

## Live tests

`test/live/*.test.ts` run `HttpOpenCodeClient` against the real local OpenCode service, found the way the extension finds it (`discoverServer`, from `service.json`). Every client call that does not touch your account is covered: server info, models, agents, skills, commands, file search, account state, MCP servers, the folder's project and saved rules (saved through an "always" reply, edited, refused as a duplicate and deleted), approval modes (each applied to a session, read back, and checked by what OpenCode decides for a request, which needs no model), rules from the event stream, usage limits, usage stats and a session's context messages, sessions (create, rename, archive, fork, rewind, delete, and on Windows both drive-letter forms), history, the pending lists, running state and the event stream, including what arrives for a session that is not open (the session strip and its notices). Each test asserts the parsed shapes the UI uses. `test/live/providers.test.ts` covers provider setup without touching any credential: the integration and provider lists, one integration and the `404` for an unknown one, every connect call refused for an unknown integration, the config reload (also with a deleted folder still loaded; only with `OCS_LIVE_RELOAD=1`, since a reload rebuilds every folder under the tests running beside it), a run on a model OpenCode does not have (its error card, without a model call) and the setup check against the real service. `test/live/agents.test.ts` writes agent files into a temporary folder (never OpenCode's global config) and checks what OpenCode lists for them: the fields Sidecar writes, an edit that keeps a comment and an unknown key, a delete, an OpenCode 1 file converted to the rules OpenCode made of it, an imported `.roomodes`, the config folders, and the controller waiting for an agent and refreshing the agent picker. `test/live/review.test.ts` makes OpenCode record a session diff without the model editing (two tiny prompts on the plan agent, with a CRLF file changed, a file added and one deleted, and a `!command`, between them; at the free limit the steps still record their snapshots) in a temporary Git repository, and checks the full-file patches rebuild the baseline (with the user's earlier change) and the snapshot exactly against Git and the disk, the hunks, an undo after an edit elsewhere, `git apply --cached` of the kept hunks against `git diff --cached`, and that a rewind with code leaves those files as the preview says. `test/live/mcp.test.ts` adds MCP servers for one OpenCode run in a temporary folder (never in a config): a tiny stdio server (a hand-written JSON-RPC responder run with Node) connected, disconnected, connected again and removed, one that exits as `failed` with its reason, the `404`s, `mcp.status.changed` with the folder reaching the controller, and the OAuth sign-in of a fake remote server the test serves itself (metadata, client registration, an authorize page its "browser" follows, a token, MCP over HTTP), after which the server connects; the credential is removed again. `test/live/goal.test.ts` sets a `/goal` through the controller in a temporary folder, follows OpenCode's goal plugin (its RPC and `rpc.opencode.goal.changed`), interrupts the first turn at once so the goal stops with OpenCode's reason (one tiny model call at most), reads the stored kickoff back as a goal row and ends the goal; `/goal pause` without a goal is refused with OpenCode's message. `test/live/instructions.test.ts` builds a temporary Git repository below a folder with its own AGENTS.md and checks the files Sidecar lists against the instruction hash OpenCode reports when a prompt starts (each prompt is interrupted once it arrives, also at the free limit): changing a file listed as read changes it, changing a CLAUDE.md listed as not read does not, a remembered line is read, and without AGENTS.md the CLAUDE.md beside it is; also that OpenCode offers `/init`. `test/live/client.test.ts` also reads OpenCode's voice models and checks that a voice session is refused without a provider key (Sidecar does not use voice; the check keeps the write-up in the integration notes honest). `test/live/history.test.ts` builds a session of 450 stored messages (1,200 with `OCS_LIVE_LONG=1`; delivering them keeps OpenCode's store busy for a moment, which can slow the tests beside it) without the model writing (synthetic notes held back, then delivered by one run that fails at once at the free limit) and opens it through the controller: the newest 400, whether there are more, Load earlier until all are loaded, with the load times printed. `test/live/generate.test.ts` checks OpenCode's stateless generation, used for commit messages: an unknown model's `404`, and a commit message from the free model or, at the free limit, the `502` with `rate_limit` that Sidecar reports (the reply is then skipped).

They work in a new temporary folder and delete every session they create. Four tests send a prompt to the free `opencode/big-pickle` model (skipped when it is not offered): one checks that a prompt with a large paste is stored exactly and stops the session at once, the other waits for the reply (skipped when the free daily limit is reached). A third asks a side question through the session controller: the fork, its agent and model, History leaving it out, and its deletion are always checked; its answer only when the free limit allows. Two run a session that is not open beside an open one: its run's events, strip status and notice are checked whether the run succeeds or hits the free limit; its permission request only when the model asks for one. One more checks a reply's step (its model, agent, cost and stream time, live and replayed) for the turn footer, skipped when the free limit is reached. The others make no model calls. Without a registered service, or when it does not answer, every test is skipped with the reason, so the suite also passes on CI. The service password is never printed.

```sh
npm run test:live
```

## Acceptance harness

`test/acceptance/runAcceptance.ts` launches VS Code (`VSCODE_EXECUTABLE` overrides the path) with temporary user data and `--disable-extensions`, then runs `test/acceptance/suite.ts` inside the extension host. It drives the real extension through the same handlers the webview uses, against the real OpenCode service, so **it makes real model calls**.

```sh
npm run test:acceptance                       # fixture repository scenarios
ACCEPT_REAL_REPO=/path/to/repo ACCEPT_REAL_FILE=src/a.ts ACCEPT_REAL_LINES=20-27 npm run test:acceptance
ACCEPT_ONBOARDING=1 npm run test:acceptance   # also first-run scenarios (temporary OpenCode servers)
ACCEPT_REVIEW_ONLY=1 npm run test:acceptance  # only the Keep / Undo review, without the model editing
```

The scenarios run on `opencode-go/kimi-k2.7-code` when OpenCode offers it, otherwise on the free `opencode/big-pickle`; `ACCEPT_MODEL=<provider/model>` picks another. Shell commands in the prompts work in bash, zsh and the Windows PowerShell that OpenCode uses on Windows; when the model does not run the command it is asked once more.

The real-repository scenario is read-only: it uses OpenCode's `plan` agent, fingerprints the repository's Git state before and after, and fails if anything changed.

## Packaging

`npm run package` runs the production build and `vsce package`. `.vscodeignore` is a whitelist: the VSIX contains only the two bundles, `media/main.css`, the icons, `README.md`, `CHANGELOG.md`, `LICENSE`, `SECURITY.md`, `THIRD-PARTY-NOTICES.md` and `package.json`. Uploading to the Marketplace is a manual step; see `docs/marketplace/MARKETPLACE.md`.

## Project layout

```
src/
  extension.ts   activation: view, commands, output channel, content providers
  host/          VS Code integration (webview provider, workspace and Git, diffs, editor tabs, config)
  core/          VS Code-free logic (session controller, subagents, budget, forms, context, discovery)
  opencode/      OpenCode adapter (HTTP client, service discovery, SSE, event normalization)
  shared/        types and reducers shared by host and webview
  webview/       the chat view (plain TypeScript and DOM, no framework) and Markdown parser
media/           CSS and icons (icon source in media/src/)
scripts/         build, screenshots, hero and icon rendering
test/            unit tests, webview tests, live tests, mock client, acceptance harness
docs/            architecture, development, OpenCode integration, Marketplace notes
```

The extension has no runtime dependencies to install: the UI uses plain DOM APIs, and the Markdown renderer and SSE parser are small in-repo modules. The one bundled library is [Prism](https://prismjs.com) (MIT), used only as a tokenizer for syntax colors (`src/webview/highlight.ts`); its license is in `THIRD-PARTY-NOTICES.md`, which ships in the VSIX.
